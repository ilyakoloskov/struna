# Проект: STRUNA — сервис для гитариста (PWA): тренажёр в стиле ритм-игр + музыкальная теория

## Контекст
Я фронтенд-разработчик (Vue 3, TypeScript, Composition API, Pinia, Vite) и гитарист.
Хочу сделать PWA-приложение: я подключаю гитару (6 или 7 струн) через звуковую карту,
загружаю файл трека с нотами гитарной партии, ноты едут по экрану по дорожке,
я играю, приложение в реальном времени распознаёт сыгранные ноты и начисляет очки
за попадания. По ощущениям — как Guitar Hero / Rocksmith, но с собственным оригинальным дизайном.
Кроме игры, приложение — набор инструментов для музыканта: тюнер, квинтовый круг,
ноты на грифе, гаммы и лады с подсветкой под тональность. «STRUNA» — рабочее название.
Отвечай и комментируй на русском, код и названия — на английском.

## Стек
- Vue 3 + TypeScript (strict) + Composition API + Vite
- Pinia для состояния игры и настроек
- vue-router: ленивые (lazy) маршруты, у каждого раздела свой чанк
- Web Audio API: getUserMedia + AudioWorklet для анализа звука
- Определение высоты тона: `pitchy` (McLeod) или собственная реализация YIN — предложи и обоснуй
- Парсинг MIDI: `@tonejs/midi`
- Позже: Guitar Pro файлы и рендер табулатуры через `alphaTab`
- Игровая дорожка: WebGL через Three.js (перспектива, свечение/bloom, частицы, 60 fps)
- Интерфейс поверх игры (меню, счёт, комбо, экраны) — обычные Vue-компоненты
- PWA: `vite-plugin-pwa`
- Локальное хранение (библиотека треков, рекорды, калибровка, настройки): IndexedDB через Dexie или idb-keyval — предложи
- Музыкальная теория: библиотека `tonal` (@tonaljs) или собственный модуль — предложи и обоснуй
- Тесты: Vitest для всей чистой логики (сравнение нот, очки, тайминги, расчёт ладов, теория)

## Гитара: 6 и 7 струн, строи
- Поддержка 6- и 7-струнных гитар; количество линий на дорожке = количество струн
- Пресеты строя: 6 стр. Standard (E A D G B E), 6 стр. Drop D, 6 стр. Eb Standard,
  7 стр. Standard (B E A D G B E), 7 стр. Drop A; плюс пользовательский строй (нота каждой струны)
- Строй — единый источник правды: от него зависят тюнер, расчёт ладов из MIDI и подписи струн
- Самая низкая нота может быть около 55 Гц (Drop A): окно анализа детектора должно быть
  достаточно длинным для низких частот; найди баланс между точностью на низах и задержкой
  (например, адаптивный размер окна или отдельная настройка) и объясни выбор
- Для MIDI (где нет струн/ладов) вычислять позицию ноты под выбранный строй:
  предпочитать удобные позиции и минимальные перемещения руки
- Засчитывать ноту по высоте (MIDI-номер), а не по струне/ладу: одна нота играется в разных позициях

## Структура приложения (роутер)
- `/` — главная: быстрый доступ к игре, тюнеру и теории
- `/library` — библиотека треков
- `/play/:trackId` — игра
- `/results/:sessionId` — результаты
- `/tuner` — тюнер
- `/theory/circle` — квинтовый круг
- `/theory/fretboard` — ноты на грифе, гаммы и лады
- `/settings` — вход звука, строй, калибровка, вид
- Общий layout с навигацией; на экране игры навигация скрыта (полноэкранный режим)
- Выбранные тональность, лад и строй — в Pinia и в query-параметрах URL, чтобы ссылкой можно было поделиться (например, `/theory/fretboard?key=E&mode=phrygian&tuning=7-standard-b`)

## Модуль теории («сервис для музыканта»)
Вся теория — чистые функции в отдельном доменном модуле (например, `src/domain/theory`), без Vue внутри, с тестами.
- Ноты, интервалы, гаммы, аккорды; правильное энгармоническое написание по тональности
  (в фа мажоре — B♭, а не A♯; в фа-диез мажоре — E♯)
- **Квинтовый круг**: интерактивный SVG; внешнее кольцо — мажорные тональности, внутреннее — параллельные миноры;
  клик по сектору выбирает тональность; показывать число и список знаков, соседние тональности,
  диатонические аккорды (I ii iii IV V vi vii°) с функциями (T / S / D)
- **Гриф**: все ноты под текущий строй (6/7 струн, до 24 ладов), отметки ладов (3, 5, 7, 9, 12…);
  подсветка нот выбранной тональности/лада; цвет по роли: тоника, терция, квинта, остальные ступени;
  переключатель подписей: названия нот / ступени / интервалы; выбор диапазона ладов;
  по клику нота проигрывается синтезатором
- **Гаммы и лады**: мажор, натуральный минор, 7 церковных ладов, гармонический и мелодический минор,
  мажорная и минорная пентатоники, блюзовая гамма; позже — позиции/боксы и CAGED
- **Живой гриф**: при игре на гитаре распознанная нота подсвечивается на грифе во всех позициях
  (переиспользуем движок тюнера); отдельно отмечать, входит ли нота в выбранную гамму
- **Связь с тренажёром**: из теории можно запустить упражнение «сыграй гамму вверх-вниз» с проверкой по распознаванию
- Цвета струн и стиль — те же дизайн-токены, что в игре

## Требования к распознаванию и игре
- getUserMedia с echoCancellation, noiseSuppression, autoGainControl = false
- Выбор устройства ввода (звуковой карты) из списка, индикатор уровня сигнала
- Анализ звука только в AudioWorklet, без блокировки UI
- Допуск по высоте ±50 центов; учитывать октавные ошибки детектора
- Детектировать начало ноты (onset), чтобы одна долгая нота не засчитывалась многократно
- Порог громкости, чтобы шум и затухающие струны не давали ложных срабатываний
- Окна попадания по времени: Perfect / Good / Miss (например, ±50 / ±120 мс) — в конфиге
- Калибровка задержки: пользователь играет ноты по метроному, смещение сохраняется
- Логику аудио, игры и рендера держать в отдельных модулях/composables, не смешивать с компонентами

## PWA
- Устанавливаемое приложение: manifest, иконки, цвет темы, display: fullscreen/standalone, ориентация landscape
- Офлайн: кэш оболочки через service worker, запуск без сети
- Загруженные треки хранятся в IndexedDB и доступны офлайн
- Screen Wake Lock API во время игры
- Главная платформа — десктопный Chrome/Edge со звуковой картой; на мобильных работает
  с микрофоном, но с честным предупреждением о большей задержке
- getUserMedia требует HTTPS (localhost подходит для разработки)

## Визуальный стиль
Ориентир — ощущения ритм-игр (Guitar Hero, Rocksmith), но полностью оригинальный дизайн:
никаких логотипов, названий, ассетов и фирменных элементов этих игр.
Референс — папка `/design`: PNG-экраны, их статичная HTML-разметка в `/design/html`
и токены в `/design/tokens.md`:
- `01-game-7-strings.png`, `02-game-6-strings.png` — игра
- `03-tuner.png` — тюнер
- `04-results.png` — результаты
- `05-circle-of-fifths.png` — квинтовый круг
- `06-fretboard.png` — гриф и лады с живой подсветкой
Повторяй стиль, цвета и композицию; цифры и названия на макетах — примерные.
Главного меню, библиотеки и настроек в концепте нет — делай их в том же стиле.
- Тёмная тема, неоновые акценты, глубина, свечение (bloom)
- Дорожка в перспективе, уходящая вдаль; N линий = N струн, у каждой струны свой постоянный цвет
- Палитра на 7 струн; для 6-струнной гитары используются те же цвета без самой низкой струны
- Нота — светящийся «камень» на линии своей струны с номером лада на нём;
  длинные ноты — с «хвостом» длительности
- Линия удара внизу с подписями струн (нота строя); при попадании — вспышка, частицы, пульсация
- Всплывающая оценка: Perfect / Good / Miss
- HUD: счёт, комбо, множитель ×1…×4 (растёт с серией), точность, полоса прогресса трека,
  название трека и строй
- Экраны: главное меню, библиотека треков (карточки: название, строй, сложность, лучший результат),
  настройки (вход звука, строй, калибровка), игра, пауза, результаты (точность, макс. комбо, оценка/звёзды)
- Плавные переходы между экранами; игра держит стабильные 60 fps:
  никаких аллокаций в цикле рендера, пул объектов для нот и частиц
- Уважать prefers-reduced-motion: режим без тряски и вспышек
- Дизайн-токены (цвета струн, неон, фоны, шрифты, радиусы) — в одном месте

## Этапы (делаем строго по очереди)

### Этап 2. Тюнер (`03-tuner.png`)

### Этап 3. Теория (`05-circle-of-fifths.png`, `06-fretboard.png`)

- Готово, когда: тесты теории зелёные, выбор тональности/лада сохраняется в URL, живой гриф работает с гитарой

### Этап 4. Загрузка MIDI
- Выбор файла, выбор гитарной дорожки, список нот (время, высота)
- Расчёт струн/ладов под выбранный строй, воспроизведение остальных дорожек (или метроном на старте)
- Готово, когда: загруженный MIDI проигрывается, ноты гитарной партии видны списком со струной и ладом

### Этап 5. Дорожка (`01-game-7-strings.png`, `02-game-6-strings.png`)
- Three.js: перспектива, линии струн, ноты-«камни» с ладом, хвосты длинных нот, линия удара
- Сначала тестовые ноты без звука, затем синхронизация с воспроизведением
- Готово, когда: стабильные 60 fps, ноты приходят на линию удара точно в своё время

### Этап 6. Игра (`04-results.png`)
- Сравнение сыгранного с ожидаемым, окна Perfect/Good/Miss, очки, комбо, множитель, эффекты попаданий
- Экран результатов: оценка, точность по ходу трека и по струнам
- Готово, когда: можно сыграть трек от начала до конца и получить результат

### Этап 7. PWA и хранение

### Этап 8. Удобства

### Этап 2. Тюнер — реализован, ждёт проверки с реальной гитарой
- Детектор — свой YIN (`src/audio/dsp/yin.ts`), без зависимостей и аллокаций в detect().
  Минимум ищется по всей ширине первого провала ниже порога (а не до первого локального минимума):
  иначе на тихом хвосте низких нот шум давал ошибку до +30 центов
- Перед детектором ФНЧ-биквад 2-го порядка (`dsp/biquad.ts`), срез ≈ 1.5 × верхней границы (~2.1 кГц)
- Окно из строя (`dsp/analysisConfig.ts`): кадр = 2 периода самой низкой струны − 15 % (Drop A ≈ 2054 сэмпла ≈ 43 мс,
  Standard E ≈ 29 мс), шаг анализа фиксированный 512 сэмплов (~10 мс); верх — 24-й лад самой высокой струны.
  Стоимость: до ~1 мс на кадр (A1/шум), на тишине детектор не запускается (гейт −60 dBFS в ворклете)
- Ворклет `src/audio/worklets/pitch-processor.ts` грузится через `?worker&url`; берёт самый громкий канал входа
- `src/audio/audioInput.ts` — один вход на приложение (класс без Vue); `resume()` ждём ≤ 300 мс, иначе UI просит жест
- Стабилизатор (`dsp/stabilizer.ts`): гейт по RMS/clarity → медиана 5 → гистерезис ноты 3 кадра → EMA 0.25 → удержание 1.2 с
- Строи — `src/domain/music/tunings.ts` (id: `7-standard-b`, `7-drop-a`, `6-standard-e`, `6-drop-d`, `6-eb-standard`, `custom`);
  E♭ Standard пишется бемолями
- Показания тюнера — чистая функция `src/domain/tuner/reading.ts`: авто-режим (ближайший полутон) или закреплённая струна
- Настройки (строй, свой строй, вход, A4) — Pinia `src/stores/settings.ts`, пока в localStorage
- Проверено в Chrome с подменённым входом (сгенерированный щипок): E2 +4 ц и A1 −12 ц держатся ровно

### Этап 3. Теория — реализован, ждёт проверки живого грифа с гитарой
- Свой доменный модуль `src/domain/theory` без зависимостей (решение: не tonal). Нота = буква + альтерация (−2…2),
  ступень = номер + альтерация от мажора; `transpose` пишет ноту по букве ступени → F мажор: B♭, F♯ мажор: E♯, G♯ гарм.: F𝄪
- Модули: notes, intervals (подписи ступеней и интервалов «м3», «ув4»), scales (12 гамм/ладов, роли тоника/терция/квинта,
  `describePitch` — нота вне гаммы пишется по хроматической ступени от тоники), chords (трезвучия, римские цифры,
  функции по ступени: I/iii/vi — T, ii/IV — S, V/vii° — D), keys (знаки, параллельная = relative, одноимённая,
  соседи, данные круга), names (русские названия), fretboard (позиции, отметки ладов), selection (query ↔ выбор)
- «Параллельная» — в русском смысле (E мажор ↔ C♯m); переключатель «Мажор/Минор» на круге — одноимённая (E ↔ Em)
- Стор `src/stores/theory.ts` (тоника, лад, подписи, диапазон ладов); строй — общий из настроек
- URL (`useTheoryQuery` в TheoryLayout): `key`, `mode` (+ синонимы major/minor), `labels`, `frets` (умолчания не пишутся),
  `tuning` — пресет или `custom-C2-G2-…`; ссылка с tuning меняет общий строй приложения (решение пользователя)
- Синтезатор — свой Karplus–Strong (`src/audio/synth`), целый период + playbackRate для точной высоты (±5 ц, проверено YIN)
- Живой гриф переиспользует `useAudioInput({ autoStart: false })` + `usePitchDetector`; нота по `pitch.note` (после гистерезиса)
- Интервалы на грифе показываются заглавными («Б2»): строчная «б» в мелком жирном шрифте читается как «6»
- Цвета ролей и функций — токены `--role-*`, `--function-*`
- Ручная проверка: `docs/checklists/stage-3-theory.md`

### Этап 4. Загрузка MIDI — реализован, ждёт ручной проверки на своих MIDI
- Зависимости: `@tonejs/midi` (разбор MIDI и карта темпов), `smplr` (сэмплы: GM soundfont + LinnDrum, решение пользователя)
- Модель трека без привязки к формату — `src/domain/tracks/types.ts` (Song, SongTrack, NoteEvent в секундах, сетка долей)
- `midiImport.ts`: дорожки без нот отбрасываются, индекс сохраняется; `guessGuitarTrack` — семейство guitar (+10),
  «guit/gtr/гитар» в названии (+5), bass (−5), затем больше нот. `midiText.ts`: названия из байтов — UTF-8, затем
  Windows-1251 (если получилась кириллица и нет слов вперемешку с латиницей)
- `fingering.ts`: Витерби по группам одновременных нот; состояние = (раскладка аккорда, позиция указательного пальца p,
  рука берёт p…p+3); стоимость = сдвиг руки (дёшево внутри «коробки», дорого дальше, вдвое дешевле после паузы ≥ 0.6 с)
  + лады (выше 12-го дороже) + растяжка + смещение по струнам. Аккорд: разные струны, без перекрёста, растяжка ≤ 4
  (иначе ослабляем и выкидываем лишние ноты). Открытые струны руку не держат. Вне строя — `stringIndex = −1`
- Один AudioContext на всё приложение (`src/audio/context.ts`): вход, синтезатор, воспроизведение на одних часах;
  остановка входа больше не останавливает контекст
- Транспорт `src/audio/playback/transport.ts`: упреждающее планирование (тик 25 мс, окно 150 мс) по часам AudioContext,
  отсчёт такта, метроном (свои щелчки-осцилляторы), гитарную дорожку можно заглушить/включить на ходу
- Голоса `instruments.ts`: имя soundfont из названия GM (+10 исключений, тест сверяет все 128 программ со списком smplr);
  ударные — DrumMachine `LM-2` с таблицей GM-нота → группа. Сэмплы кэшируются через Cache API (`struna-samples`)
- Библиотека `src/stores/library.ts` — пока в памяти; демо-трек `demoSong.ts` (свой рифф, 100 bpm, 8 тактов)
- Список нот виртуализирован (рисуются только видимые строки)
- Ручная проверка: `docs/checklists/stage-4-midi.md`
